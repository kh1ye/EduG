# TraceCon

Trace-based Memory Consolidation（基于操作轨迹的记忆巩固）。核心检验是用户反馈能否定位到一次有证据支持的历史记忆操作。

在仓库根目录运行 `python -B -m tracecon.smoke`。需要 Python 3.10 或更新版本，使用 Python 自带的 SQLite 和临时目录。退出码 0 与 JSON 中的 `passed` 表示合成回放通过。该命令使用构造事件，不读取基准答案或调用远程模型。

| 代码 | 职责 |
|---|---|
| `memory.py` | 用 SQLite 保存操作、版本、答题时实际传入的证据和反馈。独立记录观察步骤和生效区间，按半开区间查询。已有命名空间的操作和答案按步骤顺序处理，重试使用同一标识与载荷。 |
| `rollout.py` | 用已冻结的 rollout 计算 PPO 所需的 critic target 和 actor advantage。延迟反馈只进入目标操作的 actor advantage。 |
| `smoke.py` | 用合成事件检查错误覆盖、错过正确更新、取旧、生成错误、时间隔离、持久化和信用去重。 |

## 接入顺序

1. 以源历史 ID 作为 `episode`。从当前可见对话抽取 `Fact`，其中 `target` 包含实体或事件实例和属性。用 `allowed` 取得动作掩码，由策略选择动作后调用 `apply`。跨越多个当前版本的候选需在上游拆分为互不冲突的时间范围。Archive 是逻辑归档，用户删除由上游隐私接口另行处理。
2. 用 `lookup` 查询给定目标和参考时间。回答完成后，调用 `record_answer` 保存模型实际收到的版本和提取出的回答主张。每条历史由单一回放驱动顺序执行。正式检索器需要遵循同一历史隔离、时间检查和预算。
3. 用 `observe` 保存反馈原文，以 `Support` 描述经解析和语义核验的原文片段。调用 `credit` 时传入已解析的目标、生效区间和信号。现有实现检查原文片段、版本、回答和操作后果，文本语义由上游解析器提供。隐式反馈需要明确链接，并需要原文中的理由或后续确认。合成回放使用等权，真实校准仅使用开发数据。一个子句对应一个稳定事件 ID，归因逻辑由收到反馈的回放驱动调用。
4. 用 `direct_rewards` 和 `ppo_targets` 组装训练目标。现阶段实现了答案关联的结构化归因和目标计算。自然语言解析、直接评价某次操作、完整 PPO 优化循环、LACE 奖励及 LoCoMo/VatsalaBench 适配器待接入。历史受控实验仍由原脚本复现。
